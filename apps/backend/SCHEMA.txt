SCHEMA - Backend (apps/backend)

1. Resumen
- Proyecto: backend de Find Matching Jobs.
- Stack: NestJS (v11), TypeScript, TypeORM, PostgreSQL, Passport (JWT + Google OAuth).
- Propósito: API REST para gestionar usuarios, perfiles, skills, jobs y la lógica de matching entre estudiantes y vacantes. Incluye integración con JSearch (RapidAPI) para sincronizar vacantes y una capa de matching que puede usar una API generativa (Gemini) para enriquecer justificaciones.

6. Autenticación y autorización
- Passport con JWT (`jwt.strategy.ts`) y guardias (`jwt-auth.guard.ts`).
- Google OAuth: `passport-google-oauth20` con `google.strategy.ts`; el flujo guarda/actualiza `googleId` y `avatar` cuando corresponde y el callback redirige al frontend (`FRONTEND_URL`) con el token.
- Roles: `roles.decorator.ts` y `roles.guard.ts` para control de acceso por rol (ej. `UserRole.ADMIN` para `jobs.sync`).

7. Endpoints y contratos esperados (resumen)
- Auth
  - POST `/auth/login` -> login con email/password (devuelve `AuthResponseDto` con `access_token` y `user`).
  - POST `/auth/register` -> registro de usuario.
  - GET `/auth/google` -> iniciar OAuth con Google (redirect)
  - GET `/auth/google/callback` -> callback de OAuth (redirige a frontend con token)
- Users
  - CRUD / endpoints para gestión de usuarios en `users.controller.ts`.
- Profiles
  - POST `/profiles` -> crear perfil (protegido)
  - GET `/profiles/me` -> obtener perfil del usuario autenticado
  - PATCH `/profiles/me` -> actualizar perfil del usuario autenticado
- Skills
  - Endpoints para catálogo (`skills`) y `student-skills` (gestión de habilidades del estudiante).
- Jobs
  - GET `/jobs` -> listar vacantes en DB local
  - GET `/jobs/search` -> búsqueda local con filtros
  - GET `/jobs/:id` -> obtener vacante por id
  - POST `/jobs/sync` -> sincroniza vacantes desde JSearch (requiere rol ADMIN)
- Matching
  - POST `/matching/sync` -> ejecutar matching del estudiante actual vs vacantes activas (query `useAI` opcional)
  - GET `/matching/my-matches` -> resultados de matching del estudiante autenticado
  - POST `/matching/job/:jobId` -> calcular y guardar matching para una vacante específica (query `useAI` opcional)
